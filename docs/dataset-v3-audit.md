# dataset/v3 数据质量验收

## 结论

本批数据可以证明 schema v3 采集链路可用，并可作为机器人 ETA 的第一批训练数据；球模型仍不应直接定版。主要原因不是 JSONL 总量不足，而是踢球力度没有覆盖、严格干净自然停球较少，以及场外球被重复识别为多个短运动段。

## 文件与完整性

- 文件：`dataset/v3/match_dataset.team1.jsonl`
- 大小：77,630,377 bytes
- JSON 记录：8,150 条，解析失败 0 条，全部为 `schema_version=3`
- `frame`：6,981 条，约覆盖 698 秒（10 Hz）
- 比赛状态覆盖：`PLAYING` 3,471 帧、`READY` 2,463 帧、`SET` 391 帧、`FINISHED` 649 帧
- 没有 `session_end`：说明 Agent 未正常关闭或文件在关闭前被复制；但数据已覆盖到官方 `FINISHED`，主体比赛并未缺失

后续版本会在首次收到 `FINISHED` 时额外写入并刷盘 `match_end`。`session_end` 仍只代表 Agent 正常关闭和写队列完全排空。

## 球模型数据

- 32 次己方踢球的 `power` 全部为 `1.5`
- 168 条球运动段中：自然停止候选 38、边界/门线几何终止 107、己方新踢球截断 21、官方状态终止 2
- 严格 `free_roll_terminal_candidate=true` 仅 5 条
- 质量标志：边界 108、机器人接触候选 60、速度突增候选 49、方向变化候选 25、近门柱候选 4
- 13 条延迟官方标签包含：7次进球确认、4次界外球、1次角球、1次球门球

大量几何终止段只有2～3个点。原因是球已经越界后仍有小幅位置更新，检测器会立即重新起段并再次判越界。修复方式是“场外锁存”：整球回到场内前禁止新起段，回场的裁判摆球也只用于重置历史，不作为运动。

当前38条自然停止中，5条严格干净；其余大多确实靠近机器人并伴随变向或速度突增。接触标志是公开位姿推断，不是仿真碰撞真值，因此原始距离和轨迹仍应保留，离线时可以调整阈值并使用碰撞前前缀。

## ETA 数据

- ETA 段 905 条
- 完整到达 141 条，其中训练候选 140 条
- 目标变化截断 731 条；这符合动态角色/动态目标的比赛特征，不能当作完整 ETA
- 起始目标距离：中位数 1.59 m，P90 3.79 m，最大 9.27 m
- 起始路径朝向误差绝对值：中位数 0.69 rad，P90 1.93 rad，最大 3.13 rad
- 线速度主要集中在 `0 / 0.3 / 0.8 m/s`
- 角速度大量达到 `1.0 rad/s`

起始距离和朝向覆盖已经较好，当前短板是线速度上限单一。角速度暂不探索，避免与线速度同时变化后难以归因。

## 下一轮有限探索

采用确定性轮转，单个样本内保持固定：

- 踢球力度：`1.00 / 1.25 / 1.50 / 1.75 / 2.00`
- 线速度上限：`0.40 / 0.60 / 0.80 m/s`
- 角速度上限维持 `1.0 rad/s`

第一轮验收门槛：

1. 每个踢球力度至少出现5次实际踢球，且档位计数近似均衡；
2. 每档至少获得3条严格干净自然停止，用于判断档位是否可用，未达到时继续补跑；
3. 每个线速度档至少获得30条完整到达 ETA；
4. `match_end` 必须存在，正常停止 Agent 时还应存在 `session_end`；
5. 场外连续2～3点重复球段应消失；
6. 仍按力度、初速度、距离、起始朝向、角色和是否绕障分层统计，不以总文件大小作为达标依据。

达到第一轮门槛后再评估是否需要扩大样本量。最终球模型建议每档至少20条干净完整停止轨迹；在此之前，优先补齐低覆盖档位，不扩大功率范围。
