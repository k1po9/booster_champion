# 核心预测能力接口原则

> 状态（2026-07-18）：接口原则已冻结；schema v4 球短期路径与动态机器人 ETA 均已按本文封装，并以置信度门控方式进入 Champion。ETA 仍是软排序/拦截能力，不允许作硬到达承诺。

## 1. 分层原则

1. **球物理模型保持纯净**：只使用带时间戳的球位置和观测置信度，不把角色、对手意图或传球策略塞入自由滚动模型。
2. **机器人 ETA 复制真实控制链**：转向、启动、加速、巡航、减速、最终对齐和绕障都必须与实际 `MotionController` 的行为一致。
3. **能力层与策略层分离**：球路径和机器人 ETA 是纯预测能力；拦截、传球、守门和角色分配在组合层使用它们。
4. **决策不只消费点估计**：正式输出必须包含不确定度、可用性和失效原因，供策略保守门控。

## 2. 自由滚动球能力

### 最小输入

```text
BallObservation
├── t_sec
├── x
├── y
└── confidence
```

模型应提供显式分段/重置入口，并保留原因：

```text
reset(reason)
```

典型原因包括新踢球、方向突变、位置跳变、断帧、边界碰撞、可能的机器人再触球和裁判重置。

### 正式输出语义

```text
BallTrajectoryPrediction
├── observed_at
├── current
├── velocity
├── motion_state
├── position_at(t)
├── velocity_at(t)
├── stop_point
├── time_to_stop
├── valid_horizon_sec
├── confidence_at(t)
├── uncertainty_at(t)
├── segment_id
└── invalid_reason
```

- 不强制模型每 tick 分配整条离散轨迹；允许用 `position_at(t)` 等常数或有界查询接口减少开销。
- 模型未热身、轨迹不稳定或预测超出有效时域时，必须明确降级，不得伪造高置信度路径。

## 3. 机器人目标 ETA 能力

### 正式输入语义

```text
RobotArrivalQuery
├── now_sec
├── robot_id
├── pose(x, y, theta)
├── observed_linear_speed
├── observed_yaw_rate
├── raw_target(x, y, theta)
├── adjusted_target / planned_path_length
├── arrive_distance
├── arrive_angle
├── runtime_mode / fall_state / kick_state
├── target_age_sec
└── target_changed
```

- 不得只用直线距离；预测输入必须能表达当前朝向、当前运动、刚换目标、实际绕障路径和不可行动状态。
- 无法可靠获得某个可选输入时，必须用明确的缺失值和增大不确定度处理，不得将缺失当作零。

### 正式输出语义

```text
RobotArrivalEstimate
├── eta_sec
├── earliest_sec
├── latest_sec
├── uncertainty_sec
├── reachable
├── invalid_reason
├── turn_time_sec
├── startup_time_sec
├── travel_time_sec
├── braking_time_sec
├── final_align_time_sec
├── path_length_m
├── adjusted_target
└── motion_phase
```

## 4. 组合能力

球路径与 ETA 在拦截层组合：

```text
p_ball(t) + ETA(robot, p_ball(t))
    -> 最早满足 ETA <= t + safety_margin 的相遇点
```

```text
InterceptEstimate
├── robot_id
├── intercept_point
├── intercept_time_sec
├── robot_eta_sec
├── arrival_margin_sec
├── confidence
├── fallback_point
└── reason
```

这一层才负责传球接收者、动态 Handler、守门拦截和球权互斥；底层两个预测模型不直接分配角色。

## 5. 性能、验证与接入门槛

- 正式在线能力只使用 Python 标准库，不依赖 PyTorch、NumPy 或其他新包。
- 单次预测和一次 ETA 查询必须是常数或有界小规模计算；拦截搜索只使用固定数量的候选时间点和最多一次局部细化。
- 模型参数必须离线拟合并固化；在线不训练、不读取外部模型文件、不使用随机探索。
- 以整场比赛文件为留出单位，不得将同一次踢球或同一目标事件的相邻帧拆分到训练集和验证集。
- 模型达标前只允许离线验证或 shadow 日志；不接管 Chaser、传球、守门或默认角色分配。
- 正式封装后仍必须保留当前球位/保守 ETA 回退和独立开关。

## 6. schema v4 球路径接口落地

实现位于 `src/tactics/ball_trajectory.py`，固化参数位于 `src/tactics/ball_event_model_data.py`。策略公共入口为：

```text
BallTrajectoryObservation       # 避免与旧 v1 BallObservation 混淆的包级别名称
EventBallTrajectoryPredictor    # 自动检测加速、5点热身、交互重置
BallTrajectoryPrediction        # 不可变查询结果
predict_launched_ball_path      # 已知启动分段时的纯函数入口
```

时间语义必须严格区分：

- `position_at(t)` 中的 `t` 相对预测的 `observed_at_sec`；
- `position_ahead(now, dt)` 才表示“从当前时刻再往后 `dt` 秒”；
- `valid_horizon_sec=1.0` 只表示模型存在经验证的查询点；
- `recommended_horizon_sec=0.5` 是当前允许策略软使用的上限；
- `is_strategy_usable(...)` 同时检查预测年龄、推荐时域、置信度和不确定度。

当前模型不声称最终自由停止已经达标，所以 `stop_point` 和 `time_to_stop_sec` 明确返回 `None`。发生断帧、位置跳变、方向突变、突然减速、二次加速、边界/门柱/机器人接触或裁判重置时，调用方必须保留或主动触发 `reset(reason)`。预测不可用时返回带 `invalid_reason` 的对象，而不是伪造路径。

模型只消费球位置、时间戳和观测置信度；机器人、边界、门柱和角色仍然只在事件截断与策略组合层使用。运行时参数是 Python 常量，不读取 JSON，不训练，也不依赖 NumPy、PyTorch 或其他第三方包。
