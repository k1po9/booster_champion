# 球路径、机器人 ETA 与拦截接口

公共接口从 src/tactics/__init__.py 导出。它们是无命令副作用的战术能力：只读取调用方提供的公开状态并返回不可变结果，不分配角色、不发送运动命令、不处理 GameController 合法性。

## 1. 球路径接口

### 1.1 主要类型

- BallObservation：时间戳、球队视角球坐标和置信度。
- BallPathKnot：一个未来时距的球位置、速度、不确定度和置信度。
- BallTrajectoryPrediction：完整只读预测，包含模型名、运动状态、分段号、有效时域和无效原因。
- EventBallTrajectoryPredictor：在线事件检测、五点窗口和分段管理器。
- predict_launched_ball_path：对已准备好的启动后观测执行一次纯预测。

### 1.2 在线调用

~~~python
predictor = EventBallTrajectoryPredictor()

# 只在出现新球时间戳时添加
predictor.add_ball(context.known_ball)
prediction = predictor.predict()

if prediction.is_strategy_usable(
    now_sec,
    0.25,
    min_confidence=0.35,
    max_uncertainty_m=0.45,
):
    point = prediction.position_ahead(now_sec, 0.25)
else:
    point = prediction.current
~~~

position_at(t) 的 t 相对 observed_at_sec；position_ahead(now, dt) 会自动加上缓存预测已经过去的年龄，适合策略层查询从现在起 dt 秒。接口不允许在有效时域之外外推。

常见 invalid_reason 包括预热不足、观测窗口过长、球已停止或不可观测。调用方只应判断 usable 和门控方法，不应根据某个具体字符串绕过回退。

## 2. 机器人 ETA 接口

### 2.1 主要类型

- RobotMotionTracker / RobotMotionEstimate：从最近公开位姿估计线速度和角速度，缺失时允许 ETA 降置信度运行。
- RobotArrivalQuery：一次到达查询的完整输入。
- RobotArrivalEstimate：ETA、最早/最晚区间、置信度、可达性、模型选择和运动诊断。
- DynamicRobotArrivalEstimator：动态选择基线或 team2 固化参数。

### 2.2 查询输入

~~~python
query = RobotArrivalQuery(
    now_sec=now_sec,
    robot_id=player_id,
    pose=robot_pose,
    raw_target=target,
    linear_speed_limit_mps=max_speed,
)
estimate = DynamicRobotArrivalEstimator().estimate(query)
~~~

为了获得更可信的区间，调用方还应尽量提供：

- adjusted_target 和 planned_path_length_m：避障或目标约束后的实际路线；
- observed_linear_speed_mps、observed_yaw_rate_radps：公开位姿窗口估计；
- arrive_distance_m、arrive_angle_rad：调用场景的到达定义；
- command_speed_mps、command_yaw_rate_radps：最近实际命令；
- target_age_sec、target_changed、motion_phase：稳定目标和运动阶段；
- runtime_mode、fall_state、kick_active：当前是否允许正常行走。

### 2.3 输出契约

~~~python
if estimate.reachable and estimate.eta_sec is not None:
    soft_cost = estimate.eta_sec + 0.20 * estimate.uncertainty_sec
else:
    # 使用几何距离/转向代价或当前策略回退
    ...
~~~

关键字段：

- eta_sec：选中模型并经过物理下界修正的点估计；
- earliest_sec / latest_sec：由留出误差、域距离、缺失输入和双模型分歧扩大的区间；
- confidence：只用于软门控，不代表到达概率；
- model_name、alternate_model_name、alternate_eta_sec、selection_reason：动态选择的可审计信息；
- invalid_reason：不可达原因，如非有限输入、非法路径或速度、正在踢球、非直立或不可行走模式；
- adjusted_target、path_length_m、motion_phase：调用上下文诊断。

接口不会读取路径规划器。如果调用方没有提供实际绕障路径，它只能按直线路径估计，并会增加不确定度。

## 3. 最早拦截接口

estimate_earliest_intercept 组合球路径和 ETA，但只检查固定候选时点，默认是 0.10 / 0.25 / 0.50 秒，因此不会执行无界数值求解。

~~~python
result = estimate_earliest_intercept(
    estimator,
    base_query,
    trajectory,
    safety_margin_sec=0.35,
)

target = (
    result.intercept_point
    if result.intercept_time_sec is not None
    else result.fallback_point
)
~~~

成立条件是机器人 ETA 加安全余量不晚于球到该点的时间。InterceptEstimate 同时返回机器人 ETA、时间余量、置信度、具体原因和用于回退的当前球位。

拦截时点相对查询当前时刻解释，内部会扣除球预测已经缓存的年龄。若球路径不可用、候选点超出校准时域、机器人不可达或没有满足余量的点，结果不会伪造拦截时间。

## 4. 接口稳定性原则

- 输入输出使用球队视角坐标；策略层不要再次按主客队镜像。
- 任何不可用状态必须显式返回，而不是抛出正常场景异常或填入虚假 ETA。
- 模型更新可以替换固化参数，但不应破坏上述数据类型和回退语义。
- 新调用方必须保留独立开关和旧逻辑回退。
- 预测结果不能绕过 GameController、处罚、定位球距离、跌倒恢复或最终命令安全覆盖。
