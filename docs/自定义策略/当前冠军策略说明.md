# 当前 Champion 策略说明

当前实现位于 src/play/champion.py，入口为 ChampionPlaybook。它复用既有 DataLayer、行为树、运动控制、踢球迟滞和 SafetyOverrides，只在 play 层增加有界团队决策。默认 playbook 注册为 champion。

## 1. 当前最重要的约束：唯一主动抢球权

Champion 每帧先生成一个不可变角色分配，再由三个机器人并行执行。新协调层保证启用 enable_team_coordination 时，普通比赛帧最多只有一个主动抢球角色：

| 团队状态 | 球权拥有者 | Keeper | 外场候选 1 | 外场候选 2 |
| --- | --- | --- | --- | --- |
| ATTACK | Handler | Guard | Handler | Outlet |
| DEFEND | Handler/Pressurer | Guard | Pressurer | Marker |
| KEEPER_BLOCK | Handler | Block ball-goal line | Interceptor | Marker |
| KEEPER_EMERGENCY | Keeper | Challenge/Clear | SecondBall | Marker |
| KEEPER_RECOVER | Handler | Return Guard | Handler | Marker/Outlet |

默认门将角色过去只要球进入宽泛危险区就独立追球，而 Handler 同时仍是 Chaser。现在 ChampionGoalkeeperRole 先投影球到本方球门中心的直线并封住该线；只有状态机明确授予 BallOwnerRole.KEEPER 时才允许 approach/kick，否则由外场 Handler 断球。关闭 enable_team_coordination 后恢复旧门将行为，保留完整回退。

## 2. 门将接管事务

纯状态机位于 src/tactics/team_coordination.py，状态为：

~~~text
NORMAL
  -> KEEPER_BLOCK（对手可争抢、球过快或球太深：门将封线，外场断球）
  -> KEEPER_EMERGENCY（球近、球慢且对手赶不到：门将大脚解围）
  -> KEEPER_RECOVER
  -> NORMAL
~~~

进入门将事务必须同时满足：

- 没有活动定位球，避免本地逻辑覆盖 GameController；
- 球位于现有本方危险区；
- Cover 位姿有效且距球不超过 2.20 m；
- 存在深球门走廊、球明显向本方球门滚动或对手距球不超过 1.25 m 的威胁；
- 门将 ETA 软代价或几何距离明显优于外场 Handler。

ETA 软代价仍为 eta + 0.20 × uncertainty，门将至少领先 0.35 s；ETA 不可用时要求门将距离至少领先 0.65 m，或门将已经在球的 0.80 m 内。

事务默认至少保持 0.60 s，最多 3.00 s，之后进入 0.80 s 的真实 RECOVER 保持，防止持续威胁令 EMERGENCY/RECOVER 每帧抖动。球离开危险区或确认以不低于 0.45 m/s 向前释放后，可以在最短保持结束时退出。

只有进一步满足门将距球不超过 0.72 m、球速不超过 0.35 m/s、最近对手距球至少 1.45 m，且球不在门线后 0.65 m 深区时，才进入 KEEPER_EMERGENCY 主动大脚解围。否则为 KEEPER_BLOCK：门将保持射门线，外场 Handler 继续拦截，另一先锋负责 Marker。

进入主动解围的同一角色快照中：

- Keeper 是唯一 ball owner；
- 原外场候选不再映射为 Chaser，而映射为 SecondBall；
- 另一名外场球员在有合法威胁对象时映射为 Marker；
- Handler、动作选择和 AttackWatchdog 暂停，避免继续发追球/踢球目标。

## 3. 防守 Pressurer + Marker

粗攻防判断使用公开球位和双方有效、未过期位姿：

- 球进入本方侧较深区域时进入 DEFEND；
- 球接近中场时，如果有效对手到球不晚于我方约 0.35 m，也进入 DEFEND；
- 过期或处罚中的对手不会触发状态。

DEFEND 中 Handler 继续作为 Pressurer 管球，剩余外场球员改为 Marker。Marker 从合法对手中排除距球 1.35 m 内的可能持球者，再按以下公开信息选择最危险无球队员：

- 距本方球门的距离；
- 是否位于球门正面；
- 与球的距离；
- 当前最近防守人的距离。

Marker 目标位于对手朝本方球门方向约 0.75 m 处，并面向球。标记对象使用 0.30 的切换优势门槛；新对象没有明显更危险时继续盯原对象。无合法对手时回退 Outlet，而不是伪造 Marker。

当前评分是有界手工启发式，不声称是控球权概率或传球成功概率。下一轮仿真应重点检查 Marker 是否进入门将活动区、是否频繁换人、是否真正切断致命传球。

## 4. 每帧决策链

~~~text
公开 PlayContext
  -> 有效球员和公开位姿运动跟踪
  -> 更新旧滚动球预测 + schema-v4 启动事件球路径
  -> 生成固定上界的追球目标与外场候选
  -> 门将/外场 ETA 与几何威胁证据
  -> KEEPER_BLOCK/KEEPER_EMERGENCY 事务或 ATTACK/DEFEND 状态
  -> 原子分配 Keeper/Handler/Outlet/Marker/SecondBall
  -> 压力、Watchdog、比赛风险、动作选择
  -> 既有运动控制与 SafetyOverrides
~~~

所有候选数量和查询时点有固定上界；decision_budget_ms 默认 8 ms。ChampionPerformance 记录最近窗口的平均、P99、最大耗时和超预算次数。
本机对 3 个对手的危险度选择加 Marker 目标计算基准平均约 18.7 微秒；它不是当前 8 ms 预算的主要成本。

## 5. 球预测、ETA 与 Handler

追球目标的回退顺序保持不变：

1. schema-v4 球路与动态 ETA 的 0.10 / 0.25 / 0.50 s 固定候选拦截；
2. schema-v4 默认 0.25 s 领先点；
3. SlidingWindowBallPredictor 滚动球领先点；
4. 当前公开球位。

预测目标最大混合权重为 0.55，不会完全取代当前球位。普通 Handler 排序为：

~~~text
claim_cost = eta_sec + 0.20 * uncertainty_sec + ready_slot_bias
~~~

ETA 不可达或功能关闭时回退：

~~~text
claim_cost
= distance / 0.716
+ abs(heading_error) / 0.879
+ ready_slot_bias
~~~

Handler 保留 0.35 s 切换优势和 0.60 s 冷却。门将接管只把该外场候选暂时转成 SecondBall，不销毁候选迟滞状态，RECOVER 时可以稳定恢复。

## 6. 处球与现有射门能力

Champion 继续复用：

- OpponentPressureEstimator：不高于 0.55 s 为立即压力，不高于 1.20 s 为紧迫；
- AttackWatchdog：监控 approach、align、execute，卡住后切换 escape；
- BoundedActionSelector：最多五个射门、两个传球、三个推进和危险区三个解围候选；
- KickoffTransaction：维护己方开球两触事务；
- MatchRisk、OpponentShapeTracker 与 ChampionSupporterRole。

现有射门生成五个带门柱余量的目标，并评分线路净空、转向、距离、压力和比赛风险。力度已经按动作动态输出：近射 1.45、普通射门 1.90、距离至少 3.0 m 且线路净空不低于 0.68 的 Power Shot 为 2.25；防守解围为 2.20，传球按距离限制在 1.05～1.65，推进触球为 0.85。可靠门将识别和射门窗口关闭预测仍未实现。

开球第一触目标缩短为约 (0.24, 0.10) m，力度由 0.35 降到 0.24。接球队员在第一触确认前被限制在中线后至少 0.45 m；第二阶段追短时拦截点，但球速高于 0.22 m/s 时禁止踢球，待球稳定且距球不超过 0.62 m 才进入第二踢。原开球队员同时退到固定避让点，避免两人撞到一起。

ATTACK_ISOLATE、ATTACK_COMBINE、对手看人/看球历史模型和传球后角色互换尚未实现，属于完成本轮 P0 仿真验证后的 P1。

## 7. 默认协调配置

| 配置 | 默认值 | 作用 |
| --- | ---: | --- |
| enable_team_coordination | true | 唯一球权、门将事务和团队状态 |
| enable_marker | true | DEFEND/BLOCK/EMERGENCY/RECOVER 的 Marker |
| keeper_takeover_min_hold_sec | 0.60 | 接管最短保持 |
| keeper_takeover_max_sec | 3.00 | 单次接管最长时间 |
| keeper_recover_hold_sec | 0.80 | 回位事务保持 |
| keeper_takeover_max_distance_m | 2.20 | 门将允许接管的最大距球 |
| keeper_takeover_advantage_sec | 0.35 | 门将 ETA 最小优势 |
| keeper_clear_max_ball_distance_m | 0.72 | 主动解围最大距球 |
| keeper_clear_max_ball_speed_mps | 0.35 | 主动解围最大球速 |
| keeper_clear_min_opponent_distance_m | 1.45 | 判定对手赶不到的距离门槛 |
| kickoff_first_touch_power | 0.24 | 开球短传第一触力度 |
| marker_distance_m | 0.75 | Marker 与目标的门侧距离 |
| marker_switch_margin | 0.30 | 更换盯防对象所需优势 |
| enable_prediction / enable_robot_eta / enable_intercept | true | 预测和 ETA 软能力 |
| enable_action_selection / enable_action_execution | true | 有界动作选择与执行 |

关闭 enable_team_coordination 会恢复旧 Handler + Outlet + 默认门将危险区处理；关闭 enable_marker 只回退 Supporter，不影响唯一球权事务。

## 8. 诊断、测试与仿真验收

ChampionPlaybook.diagnostics 新增：

- team_phase；
- ball_ownership.owner_id / owner_role / reason / field_candidate_id；
- marking.marker_id / opponent_id；
- 原有角色、预测、ETA、拦截、压力、watchdog、动作和性能字段。

本机纯测试覆盖状态机进入、最短保持、最大时限、RECOVER 防抖、危险对手选择、门框安全目标、滚动球接收门控和动态踢球力度。Champion 集成测试还覆盖同帧撤销 Chaser、恢复唯一 Handler 和 Marker 分配，但本机缺少项目依赖 py_trees==2.4.0，会显式跳过；必须在构建或仿真环境补跑。

下一轮仿真首先检查：

1. 开球接球队员是否始终留在中线后，第一脚是否足够短，第二人是否不再追着滚动球反复转向；
2. KEEPER_BLOCK 时门将是否稳定封住球到球门的直线，外场 Handler 是否负责断球；
3. 只有对手赶不到且球已慢下来时 Keeper 是否大脚解围，之后是否稳定回位；
4. Marker 是否盯住非持球危险对手并保持门侧；
5. SecondBall 是否与门将保持距离并接住解围二点；
6. team_phase、ownership reason 和角色日志是否与画面一致；
7. 决策 P99 是否仍低于 5 ms，硬预算是否低于 8 ms。

GameController、处罚、定位球避让、跌倒恢复和最终命令提交仍由既有 behavior tree 与 SafetyOverrides 负责，团队协调不能覆盖这些硬规则。
