# 当前 Champion 策略说明

当前实现位于 src/play/champion.py，入口为 ChampionPlaybook。它复用既有 DataLayer、行为树、运动控制、踢球迟滞和 SafetyOverrides，只在 play 层增加有界的团队决策。默认 playbook 注册为 champion。

## 1. 队伍结构

每个合法 PLAYING 决策周期先筛选有效球员，再形成：

- Cover：优先保留配置门将；门将不可用时选球队视角 x 最小、最靠近本方球门的可用球员。
- Handler：Cover 之外到追球目标代价最低的球员，唯一执行追球和处球。
- Outlet：剩余球员，执行接应和封线。

Handler 切换保留 0.35 秒优势门槛和 0.60 秒冷却，避免 ETA 抖动导致频繁换人。门将身份、少人降级和最终安全命令不由预测模型改写。

## 2. 每帧决策链

~~~text
公开 PlayContext
  -> 有效球员与公开位姿运动跟踪
  -> 更新旧滚动球预测 + schema-v4 启动事件球路径
  -> 固定三个时点组合球路径与动态 ETA
  -> 生成置信度混合的追球目标
  -> ETA + 不确定度选择 Handler，保留迟滞
  -> 敌方压力、AttackWatchdog、比赛风险和对手形态
  -> 有界动作选择与 Outlet 目标
  -> 既有运动控制和 SafetyOverrides
~~~

所有候选数量和查询时点有固定上界；decision_budget_ms 默认 8 ms。ChampionPerformance 记录最近窗口的平均、P99、最大耗时和超预算次数。

## 3. 追球目标回退链

Champion 实际 Chaser 角色通过 ChampionChaserRole.target 读取 handler_chase_target，所以通过门控后的预测目标会进入真实移动闭环。目标按以下顺序选择：

1. 对最多两个 Handler 候选，在 schema-v4 球路的 0.10 / 0.25 / 0.50 秒点做动态 ETA 拦截搜索；选最早可行拦截，并按置信度混合当前球位，最大预测权重 0.55。
2. 无确认拦截时，如果 schema-v4 球路径满足置信度和不确定度门槛，使用默认 0.25 秒领先点并平滑混合。
3. v4 不可用时，回退 SlidingWindowBallPredictor 的滚动球领先点。
4. 两种预测都不可用时，直接追当前公开球位。

任一层失败都只降低到下一层，不会阻止追球。预测开关关闭时直接恢复当前球位逻辑。

## 4. Handler 排序

启用 ETA 时：

~~~text
claim_cost = eta_sec + 0.20 * uncertainty_sec + ready_slot_bias
~~~

ETA 不可达或功能关闭时：

~~~text
claim_cost
= distance / 0.716
+ abs(heading_error) / 0.879
+ ready_slot_bias
~~~

目标相对上次移动超过 0.35 m 才视为新目标，否则累计目标年龄。这个上下文用于区分行程起点和行程中查询。当前策略没有接入完整路径规划长度，因此 ETA 会针对缺少 adjusted path 的情况扩大不确定度。

## 5. 处球与配合

Champion 还复用以下现有战术能力：

- OpponentPressureEstimator：按敌方公开位姿给出保守压力时间；未知或过期数据按紧迫处理。不高于 0.55 秒为立即压力，不高于 1.20 秒为紧迫。
- AttackWatchdog：跟踪 approach、align、execute 的进展；卡住或超时后允许 escape 动作，避免持续原地对齐。
- BoundedActionSelector：在有界射门、传球、推进和解围候选中选择动作，并用 0.18 动作切换门槛和 0.35 秒最短保持抑制抖动。
- KickoffTransaction：维护己方开球的第一触和第二触事务。
- calculate_match_risk 与 OpponentShapeTracker：根据比分、剩余时间、人数和对方公开形态调整软权重。
- ChampionSupporterRole：从两个有界候选中选择 Outlet 位置；关闭时回退默认 supporter。

这些能力都不能覆盖规则与安全层。对方定位球避让、处罚、停止、跌倒恢复、门将安全和最终命令提交仍使用既有 behavior tree。

## 6. 默认开关

| 配置 | 默认值 | 作用 |
| --- | ---: | --- |
| enable_prediction | true | 同时更新旧球预测与 schema-v4 球路径 |
| enable_robot_eta | true | Handler 排序和拦截 ETA |
| enable_intercept | true | 固定时点拦截搜索 |
| intercept_safety_margin_sec | 0.35 | ETA 必须预留的时间余量 |
| lead_horizon_sec | 0.25 | 非拦截 v4/旧模型领先时距 |
| lead_min_confidence | 0.45 | 旧预测主门槛，v4 使用保守派生门槛 |
| lead_max_weight | 0.55 | 预测点最大混合权重 |
| enable_pressure | true | 敌方压力估计 |
| enable_watchdog | true | 处球生命周期监测 |
| enable_action_selection | true | 有界动作评分 |
| enable_action_execution | true | 让选中动作进入踢球目标 |
| enable_outlet_positioning | true | Champion 接应位置 |
| enable_set_pieces | true | 定位球事务 |
| enable_baseline_shadow | true | 同帧保留默认角色分配诊断 |

球预测、ETA、拦截可独立关闭。关闭任何新能力后，策略都保留可执行的旧几何或当前球位回退。

## 7. 诊断与验证

ChampionPlaybook.diagnostics 已输出：

- Handler、Cover、当前角色和默认基线角色；
- 追球目标、球路径模型、分段和无效原因；
- Handler ETA、区间、置信度、主备模型和选择原因；
- 拦截点、球时刻、机器人 ETA、时间余量和原因；
- 压力级别、watchdog、动作选择、开球事务、比赛风险、对手形态；
- 最新耗时、平均耗时、P99、最大耗时和超预算次数。

当前本地验证覆盖纯球路径接口、动态 ETA 选择、不可达输入、运动跟踪、固定上界拦截、Handler 迟滞、预测回退和 Champion 目标接入。若本机缺少 py_trees，Champion 集成测试会跳过；完整行为树和比赛效果必须在仿真环境验证。

建议仿真 A/B 最少对比：首次触球时间、追球路径长度、跑过球次数、Handler 切换次数、ETA 区间覆盖率、拦截成功率、处理球超时、高压力出球率、进失球和胜率。模型未通过这些比赛指标前，应继续视为冠军策略的软基石，而不是硬控制器。
