# 动态三角协同策略（已落地）

本项目的正式默认比赛策略已经切换为 DynamicTrianglePlaybook。旧的固定
Chaser / Supporter / Goalkeeper 策略不再注册为默认策略，只以
LegacyPlaybook 名义保留作兼容参考。

## 在线决策链

规则守卫 → DynamicTriangleCoordinator.update → TacticalMode →
Primary / Secondary / Safety 竞标 → TacticalContext 写入共享黑板 →
三个 Player Selector 并行执行 → SafetyOverrides → CommitTeamCommands。

规则守卫、对方重启距离、处罚、跌倒恢复和最终安全覆盖仍高于普通战术。

## 战术模式

- ATTACK：我方在控制半径内且到球优势明确。
- CONTEST：双方均没有明确控制优势，Primary 追预测拦截点。
- DEFEND：对方到球明显更快，或球已进入我方半场的防守阈值。
- EMERGENCY_DEFEND：球进入门前危险纵深，Primary 立即解围，Safety
  收到门线保护目标。
- RESTART：GameController 存在 set play。对方定位球仍先由规则树执行
  强制避让；我方定位球使用动态任务结构。

## 三个动态任务槽

- Primary：唯一直接解决当前球的机器人。动作覆盖边界恢复、射门、传球、
  快速推进、带球、防守压迫、预测拦截与紧急解围。
- Secondary：传球时跑向预测接球点并发布 ready；射门时进入异侧反弹区；
  争球时覆盖预测停球/折射区；防守时站到第二道封堵线。
- Safety：始终保持 goal-side 的动态防反位置。风险越高越靠后；紧急防守
  时进入门线封堵区。Keeper 只是 READY 基础身份，不再绑定 Safety。

三人正常使用 Primary + Secondary + Safety；两人退化为 Primary + Safety；
一人由 Primary 合并承担 Safety 责任。

## 角色竞标与迟滞

Primary 成本综合平移 ETA、朝向代价和 Keeper 非危险区出击代价。平移和
转向兑现率复用了既有实验结果 0.8945 / 0.8789。新候选必须连续
role_switch_confirm_ticks 个 tick，并比当前 Primary 至少好
role_switch_advantage_sec，才能完成换人。

## 复用的旧能力

- ball_prediction.py：为争球拦截点和 Secondary 二点位置提供置信度门控预测。
- opponent_pressure.py：提供压力时间并提高反击风险；高压下优先快速处理球。
- attack_watchdog.py：只在近球处理窗口启动；卡死或超时改为快速推进脱困。
- 机器人 ETA 实验：只复用稳定的巡航/转向兑现率，没有采用证据不足的完整 ETA。

## 代码入口

- src/play/tactical.py：模式判断、竞标迟滞、团队意图和协同目标。
- src/play/dynamic_roles.py：Primary / Secondary / Safety 行为子树。
- src/play/playbook.py：DynamicTrianglePlaybook 装配与角色分配。
- src/play/nodes.py：更新战术并把 TacticalContext 写入黑板。
- src/soccer_framework/config.py：模式、迟滞和三角结构参数。
- tests/test_dynamic_triangle.py：模式、迟滞、退化和传球握手测试。
