# 进攻动作看门狗与敌方压力时间能力

> 当前状态（2026-07-14）：两个能力已作为纯模型沉淀到 `src/tactics/`，已导出公共接口并通过单元测试。它们尚未接入 chaser 行为树，不会改变当前正式策略。

## 1. 模块边界

```text
src/tactics/attack_watchdog.py
    判断一次 approach → align → execute 尝试是否完成、卡住或超时

src/tactics/opponent_pressure.py
    估计有效敌方机器人到当前球/预测球轨迹的最早压力时间
```

两个模块都不发送机器人命令、不修改裁判状态、不绕过安全行为树。`play/` 层以后根据输出选择继续射门、传球、向安全空当推进或退回默认逻辑。

## 2. AttackWatchdog

阶段：

```text
IDLE → APPROACH → ALIGN → EXECUTE
                   ↘ ESCAPE
```

默认参数：

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| `total_timeout_sec` | 4.0s | 整次处理球尝试硬上限 |
| `no_progress_timeout_sec` | 1.0s | 球距和角度都未明显改善的最长时间 |
| `approach_timeout_sec` | 2.5s | 接近阶段上限 |
| `align_timeout_sec` | 1.5s | 调整方向阶段上限 |
| `execute_timeout_sec` | 2.0s | 执行踢球阶段上限 |
| `distance_progress_m` | 0.05m | 认定球距取得进展的最小变化 |
| `angle_progress_rad` | 0.08rad | 认定方向取得进展的最小变化 |
| `ball_release_speed_mps` | 0.35m/s | 认定球已被踢出的最低速度 |

调用方必须明确决定何时 `active=True`。当前 `soccer_kick_enter_distance=2.5m` 只是踢球迟滞范围，不能单独作为“已经控球”的计时起点。角色改变、比赛状态改变和球权丢失时应传入 `active=False` 或调用 `reset()`。

示例：

```python
status = watchdog.update(
    player_id,
    AttackAttemptObservation(
        t_sec=now,
        phase=AttackPhase.ALIGN,
        ball_distance_m=robot_ball_distance,
        angle_error_rad=kick_angle_error,
        ball_speed_mps=prediction.speed_mps,
        active=has_control_candidate,
    ),
)

if status.should_escape:
    # play 层选择安全推进/传球/解围
    ...
```

输出会区分：

```text
completed
total_timed_out
phase_timed_out
stalled
should_escape
remaining_budget_sec
reason
```

`safe_action_budget(opponent_pressure_sec)` 可以把自己的剩余硬时限和敌方压力时间合成一个安全处理窗口，但它不替 play 层选择动作。

## 3. OpponentPressureEstimator

项目能公开观察敌方：

```text
player_id
pose.x / pose.y / pose.theta
last_seen_at
裁判状态中的 penalty / active 状态
```

项目不能观察敌方内部目标、控制命令、角色、意图和硬件摔倒状态。`OpponentMotionTracker` 只根据最近公开位姿估计 `vx/vy` 和 closing speed，用于诊断；正式压力时间采用更保守的假设：每个有效对手可以立即以最大速度追向目标。

默认参数：

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| `opponent_max_speed_mps` | 0.80m/s | 敌方最快追赶速度 |
| `control_radius_m` | 0.55m | 形成争抢的战术半径 |
| `prediction_horizon_sec` | 3.0s | 搜索未来争抢的时间范围 |
| `search_step_sec` | 0.05s | 移动球轨迹搜索步长 |
| `max_pose_age_sec` | 0.50s | 敌方位姿最大可用年龄 |
| `velocity_window_sec` | 0.45s | 敌方观测速度窗口 |

静止目标压力时间：

```text
T = max(0, distance - control_radius) / opponent_max_speed
```

移动球压力时间沿 `BallMotionPrediction.position_at(t)` 搜索最早满足：

```text
distance(opponent, ball(t)) <= control_radius + opponent_max_speed * t
```

示例：

```python
report = pressure_estimator.estimate(
    now_sec=now,
    opponents=context.opponents,
    ball_prediction=ball_prediction,
    game_state=context.game_state,
    opponent_team_id=config.opponent_team_id(),
)

pressure_time = report.pressure_time_sec
urgent = report.is_urgent(1.0)
unknown = report.has_unknown_pressure
```

输出包括：

```text
earliest opponent
time_to_pressure_sec
contest_point
current_distance_m
pose_age_sec
confidence
closing_speed_mps
stale_opponents / inactive_opponents
```

敌方位姿过期时不会伪造精确 ETA，而是计入 `stale_opponents`，由策略采用保守回退。

## 4. 后续接入建议

建议只在 chaser 分支加入，并保留配置开关：

```text
球仍在明显滚动
    → 使用球轨迹能力追短期轨迹/落点

进入近球控制候选区
    → 启动 AttackWatchdog
    → 计算 OpponentPressureReport

watchdog 正常且压力时间充足
    → 继续对齐并射门/传球

watchdog 超时/卡住
    → 触发安全推进、传球或解围

敌方压力早于安全动作窗口
    → 不再长时间对齐，立即快速处理球
```

真正接入前应在仿真日志增加 watchdog 状态、压力时间、触发原因和最终动作字段，然后比较：

- 平均处理球时间。
- 超时/无进展次数。
- 高压力下成功出球率。
- 脱困后重新获得球权比例。
- 因错误压力估计导致的过早解围次数。
