# 球轨迹预测能力实施计划

> 当前状态（2026-07-14）：在线预测能力已沉淀到 `src/tactics/ball_prediction.py`，默认使用交叉验证得到的平方速度阻力模型，已提供末端瞬时速度、未来位置、停球点、p75 级不确定半径、置信度和轨迹异常重置。它尚未接管 chaser 行为，仍处于可复用的 advisory 能力阶段。

本计划把“球速与停球点预测”从离线分析能力升级为可参与 3v3 比赛决策的在线战术能力。实施顺序是先用留出数据确定模型，再升级在线状态估计，最后以置信度门控的方式接入追球和接应决策。

## 1. 目标和非目标

目标：

- 每个 30 Hz 控制 tick 都能更新球的瞬时速度、未来位置和停球区域。
- 0.15 s 后可输出低权重趋势，0.25～0.35 s 后允许影响追球目标。
- 用“固定阻力 + 速度相关阻力”替代单一固定减速度假设。
- 任何低置信度、碰撞、再次触球或观测异常都自动退回当前球位置逻辑。

非目标：

- 本阶段不根据目标距离反推任意 `kick_power`。现有数据只覆盖力度 1.5。
- 不假设预测球路上没有对手；自由滚动模型与战术碰撞/拦截风险分开处理。
- 不在高级战术层绕过定位球、禁区、罚下和安全行为树规则。

## 2. 候选物理模型

交叉验证同时比较三种模型：

1. 固定减速度基线：`a(v) = a0`。
2. 线性速度项：`a(v) = a0 + k*v`。
3. 平方速度项：`a(v) = a0 + k*v²`。

线性模型的停球时间和距离为：

```text
t_stop = log(1 + k*v/a0) / k
d_stop = v/k - a0*log(1 + k*v/a0)/k²
```

当 `k` 足够小时必须回退到固定模型，避免数值不稳定。最终模型由留出比赛数据误差决定，不由公式的物理外观决定。

## 3. 数据筛选与交叉验证

工具：`tools/cross_validate_ball_motion.py`。

基本命令：

```bash
python3 tools/cross_validate_ball_motion.py \
  --input dataset/v1 \
  --output analysis/v1
```

筛选条件：

- 只使用 `end_reason=ball_settled` 的完整滚动轨迹。
- 排除起脚前的静止段和足-球接触加速段。
- 至少滚动 0.40 m，直线度至少 0.90。
- 通过平滑速度和合理减速区间排除强噪声。
- 后续采集器应增加明确的机器人接触和边界碰撞标志，替代当前的代理筛选。

交叉验证单位是“整个 JSONL 比赛文件”：每次留出一个文件验证，其他文件拟合 `a0` 和 `k`。不能随机打乱单帧，否则同一脚球的相邻帧会同时出现在训练和验证中。

评估时间点：`0.15 / 0.25 / 0.35 / 0.50 / 1.00 s`。主选择点是 0.35 s，因为这是希望预测开始实质影响追球的时刻。

## 4. 通过门槛

一个速度相关模型只有同时满足下列条件，才替换固定模型：

- 0.35 s 停球点中位误差相对固定基线改善至少 10%。
- 0.35 s 中位误差不高于 0.60 m。
- 0.50 s 的 p75 误差不高于 0.90 m。
- 各留出折中的 `a0` 和 `k` 没有数量级跳变；如果跳变，先查找场地模式或数据污染。

未达标时不代表能力无价值。可以先用在低权重轨迹趋势、支援队员站位和数据诊断中，但不得作为追球队员的唯一移动目标。

## 5. 在线预测器升级

修改 `src/tactics/ball_prediction.py`：

1. 保留最近 0.35～0.50 s 原始球位置，不再用 1.2 s 窗口平均速度冒充当前速度。
2. 对 x(t)、y(t) 执行新样本高权重的二次拟合，输出窗口末端瞬时速度。
3. 使用交叉验证选定的 `a0/k` 计算未来位置、停球时间和停球距离。
4. 输出拟合残差、轨迹稳定度、不确定半径和运动模式。
5. 检测时间倒退、长时间断帧、速度突变、方向突变和球位置跳变，发生时重置窗口。

新预测输出至少包括：

```text
velocity_x / velocity_y / speed
position_at(t)
stop_point / time_to_stop
model_name / a0 / k
confidence / uncertainty_radius
motion_state / sample_count / observation_span
```

## 6. 接入决策

第一个接入点是追球队员的“最早可达相遇点”，而不是直接追停球点。

```text
球预测轨迹 p_ball(t)
        +
机器人到达时间 ETA(robot, p)
        ->
最早满足 ETA <= t 的相遇点
```

目标使用连续权重：

```text
target = (1 - w) * current_ball + w * predicted_intercept
w = confidence_gate(prediction)
```

- 0.15 s 以前或置信度低：`w=0`。
- 0.15～0.35 s：`w` 从 0 平滑上升，不允许目标跳变。
- 置信度高且预测轨迹合法：允许以相遇点为主。
- 发生碰撞或轨迹失效：一个 tick 内退回当前球位置。

第二阶段再接入支援队员和门将：支援队员使用停球区域，门将使用球轨迹与防守线的交点。

## 7. 验证和回滚

单元测试：

- `k=0` 与原固定减速模型结果一致。
- 合成线性/平方阻力轨迹可恢复已知参数。
- 静止球、断帧、重复时间戳和方向突变正确降级。
- 相遇点始终在球场合法区域中。

回放验证：

- 保留直追当前球位置作为 A 组。
- 预测相遇点作为 B 组。
- 比较首次触球时间、无效转向次数、追球路径长度、失误越过球次数和最终控球率。

运行时开关：

- 预测能力必须有单独配置开关。
- 关闭时完全恢复当前默认追球逻辑。
- 不修改安全、裁判状态和定位球树的优先级。

## 8. 实施顺序

1. 运行交叉验证，审查每折参数和 0.15～1.00 s 误差。
2. 根据数据选择固定、线性或平方阻力模型，将参数固化到策略配置。
3. 升级在线速度估计、置信度和轨迹重置。
4. 新增机器人 ETA 和最早相遇点纯函数及测试。
5. 以配置开关和平滑权重接入 chaser，保留原路径回退。
6. 仿真 A/B 验证达标后，再扩展到 supporter 和 goalkeeper。
